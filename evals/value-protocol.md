# Value-first evaluation

The first gate is an eight-session preflight: settings and shipment from the existing quality fixtures, one explicit economical model, and plain/project-only/current/lean conditions. Product requests, public contracts and commands are identical. Project-only supplies a short conventional AGENTS.md; tack conditions install their pinned product. This is a cheap alternative baseline, not a claim that plain agents have no provider instructions.

Run `python3 evals/value.py evals/batches/value-first.json --dry-run` to inspect the jobs without model calls. Execution requires `--auth PATH --output NEW_DIRECTORY`, an already built pinned Docker image and explicit subscription authorization. Credentials stay inside disposable containers; no host mounts are used. Session limits are eight attempts, two concurrent and five minutes per implementation. No automatic retries. Infrastructure errors stop unscheduled work. Review sessions are separately bounded and reported.

`--observe DIRECTORY` counts commands and output characters in previous transcripts. Categories overlap; these are neither timings nor causal attribution. `--prepare-reviews DIRECTORY --output NEW_DIRECTORY` creates anonymous four-way production bundles and a separate mapping. Use the existing code-quality review prompt/schema and validation. Inspect blind judgments before opening the mapping. Hidden acceptance and seed-defect probes run after delivery outside model context using quality_grade.py.

The full proposed screen and decision rules are in the [implementation plan](../docs/plans/2026-10-08-value-first-workflow-implementation.md). It is conditional: do not spend 66 sessions automatically. The early pilot reuses known tasks and cannot establish generality, onboarding amortization, team benefit or maintainability. If it exposes a failure, fix or narrow the candidate before expanding. Freeze new scenarios and later-change requirements before a confirmation run.

Aim for 25% less time/input than current tack and at most 20% overhead versus project-only on routine tasks, without new critical regressions. These are targets, not results. A failed target must be reported. Token counts include cached input as a subset, not an additional charge; subscription tokens are not dollar costs. Agent judging costs are evaluation costs, not ordinary product overhead. Human review-time savings require actual timed human review.
