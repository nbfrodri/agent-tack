# Pattern rules for guard-bash.sh: one rule per line, fields separated by " | ".
#   scope | decision | pattern | reason
# Scopes:
#   client   a database client command name (decision and reason unused: "-")
#   sql      case-insensitive text, checked only in commands that run a database client
#   data     case-sensitive text, checked only in commands that run a database client
#   command  case-sensitive text anywhere in a simple command
# Decisions: ask (confirm first) or deny (refuse). Structural rules (git, rm, sudo, env,
# shells) stay in guard-bash.sh because they parse options and paths.
# Add your own rules in ${XDG_CONFIG_HOME:-~/.config}/agent-harness/guard-policy.txt with the
# same format; user rules can only add ask or deny rules, never relax these.
