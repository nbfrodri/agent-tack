Getting started

tack is one person's AI coding configuration kept in Git: the same instructions, skills, agent roles, hooks and checks on every machine and in every AI tool. Installing it links this repository into each tool's own folders, so an edit here applies everywhere.

1. Install

A release install needs Git, Bash and Python 3 and takes no manual clone:

curl -fsSL https://raw.githubusercontent.com/nbfrodri/agent-tack/main/get.sh | bash

To change tack itself, clone the repository anywhere and run ./install.sh from it. Preview first with ./install.sh --dry-run. Details: Installation.

2. Check the installation

tack doctor           # installation and current project, no writes
tack doctor --tools   # each installed AI tool instead

3. Turn tack on in a project

tack's workflow only applies in projects you enable. Inside a Git repository:

tack enable               # this clone only
tack setup                # read-only: what the project has and what is missing
tack setup --apply        # create missing AGENTS.md, CLAUDE.md, architecture and docs-map
tack set suggest --apply  # activate the sets that fit the project's files

tack enable --shared commits a .tack marker so everyone who clones the project gets it. Project setup covers the rest.

4. Work as usual

Open your AI tool in the project and describe the task. At session start tack hands the assistant the project's instructions, the workflow mode and the active sets; the assistant picks how much planning and review the task needs, makes the change, runs the project's checks and reports what was verified. See Daily use.

Daily use

You talk to your AI tool as usual; tack shapes what it knows and what it may do.

What happens in a session

MomentWhat tack does
Session startGives the assistant the project's AGENTS.md, the workflow mode, the reply style, an index of architecture and active handoffs, and the sets available. tack context prints the same.
Each messageNames the skills of the active sets to load first, and mentions sets that fit the request but are not active.
Each shell commandThe guard allows, asks about or refuses it: destructive Git, deleting outside the project, piping downloads to a shell and similar.
Before stoppingChecks for uncommitted work, documentation that should change with the code, and checks that were not run.
Commits and pushesGit hooks keep secrets out, check commit messages and tag format.

Asking for work

Describe the outcome and how you will judge it:

Fix the checkout error when the cart is empty. Add a regression test and keep the change small.

Override the level for one task by saying so: “use strict for this”. Say “keep this brief” or “explain in detail” to change one answer's length.

Long work and handoffs

For work that spans sessions, ask for a handoff. The next session, in any tool, reads it at start. Once a conversation is long, the check before stopping says when /clear is safe. Details: Daily use guide.

Using the CLI

tack manages the workflow for the Git project you are in. With no command it runs tack status. This page groups commands by task; the CLI reference lists every option.

Turn a project on and off

tack status               # activation, mode and local trust
tack enable [--shared]    # enable this clone, or commit a .tack marker
tack disable              # disable and remove the shared marker
tack setup [--apply]      # inventory, then create missing base guidance files

Choose how much process

tack mode                 # effective mode and where it comes from
tack mode auto            # let the assistant pick per task (default)
tack mode strict          # always strict in this clone
tack mode --unset         # inherit the shared or personal default
tack mode list            # every mode and when to use it

Add skills and agents

tack set list             # sets and where each is active
tack set show design      # what a set contains
tack set use design       # activate here (--global: everywhere, then ./install.sh)
tack set drop design      # deactivate
tack set suggest          # sets that fit this project's files
tack set skip NAME        # stop suggesting one

Run the project's checks

tack verify --plan        # which checks your changes select; runs nothing
tack trust                # allow tack to run this project's own commands
tack verify               # run the selected checks (needs trust)
tack verify --all         # every declared check

Checks come from the project's checks-map.json. See Checks and trust.

Change settings

tack config                         # every toggle, its value and source
tack config reply-style visual      # this project
tack config reply-style brief --shared   # commit it in tack.json
tack config reply-style detailed --global  # your default everywhere

Branches and teamwork

tack branches [--apply]             # merged local branches, and delete them
tack team --base origin/main --against origin/feat/x   # overlap and conflicts, no fetch

Records and memory

tack memory add "prefers tabs"      # a note every tool loads at start
tack log --cost                     # tokens and cost (with activity-log on)
tack lesson list                    # corrections not yet saved as rules

Keep tack up to date

tack update --check       # is there a newer release?
tack update               # move to it and rerun install.sh
tack doctor               # diagnose installation and project
tack docs                 # open this documentation

tack docs --print-path writes the page and prints its path without opening a browser, for SSH sessions or another browser.

Workflow modes

A mode sets how much planning, testing and review a task gets. Pick by risk, not by size.

ModeForWhat the assistant does
autoDefaultChooses lite, standard or strict per task and says which in one line.
liteQuestions, typos, config tweaks, small clear fixesFocused edit, relevant checks, brief summary.
standardA feature or bug fix within one areaShort task list, behavior tests, affected docs.
strictAuth, payments, migrations, data loss, securityWritten plan challenged by the critic, deeper verification and review.
unleashOnly when you choose itLong autonomous work on a branch without confirmations.

Saved modes apply to this clone (tack mode MODE), the team (--shared) or every project (--global). Make your own with tack mode new NAME --from standard. More: Optional features.

Sets

A set bundles skills, agent roles and Claude Code plugins for one kind of work. Only active sets load, because every active skill adds its description to every session.

  • Always active: core (dev-workflow, new-project, tack).
  • Per project: tack set use NAME links the set for every tool in this clone, ignored by Git.
  • Everywhere: tack set use NAME --global, then ./install.sh.
  • Suggestions: a set can match project files (tack set suggest) or words in a request; the assistant then ends its reply naming the set. tack set skip NAME stops one.

Browse every set with its contents in All sets. To add your own skill or set: Sets guide and Customization.

Checks and trust

The project's own checks, not the assistant's word, decide what is verified.

  1. Declare checks in checks-map.json: which commands run for which changed paths.
  2. tack verify --plan shows what a change selects without running anything.
  3. tack trust allows tack to execute the project's commands in this clone; it is never shared.
  4. tack verify runs the selection and reports failures and paths no check covers.

The check before stopping uses the same selection. Details: Verification.

Troubleshooting

You seeDo
The assistant ignores tacktack status: is the project enabled? Restart the AI session after changing settings.
Something looks broken after an updatetack doctor, then tack doctor --tools; rerun ./install.sh.
The guard asks about or refuses a commandRead its reason. Run the command yourself if you meant it; personal rules go in ~/.config/agent-tack/guard-policy.txt.
“uncommitted change(s)” before stoppingCommit verified work, or let the assistant explain why it stays uncommitted.
“X changed but Y did not (docs-map.txt)”Update the mapped document, or explain why it still holds.
tack verify says “Not completed”The selection ran past its time budget; run the suite directly or rely on CI.
A skill you expected is missingtack set list; activate its set with tack set use NAME.
