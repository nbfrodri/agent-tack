# Lean mode and token-saving toggles

- Status: implemented and measured (`docs/benchmarks/2026-10-04-lean.md`): lean matches lite on a bug fix and saves about 10% on a new project; the overhead is mostly the discipline's extra turns and test-command discovery.
- Goal: cut the harness's overhead on small tasks (about 2× baseline in lite, mostly input tokens) without losing branch, Conventional Commit and test discipline.
- Agreed roadmap after this plan: full tool coverage (VS Code setting, Codex agents and hooks), then the rename to repository `agent-tack` and command `tack`.

## Work and acceptance criteria

1. **`lean` mode:** a self-contained mode file (no need to load `dev-workflow`), terse replies, no plan file, handoff, AI log, review agent or delegation, affected tests only, minimal startup context. Hooks and guard unchanged.
2. **Mode files declare their startup context** (`Context: minimal | index | full`) instead of the context renderer hard-coding mode names.
3. **Token-saving toggles in `harness config`:** `reply-style` (`normal|terse`), `subagent-model` (`inherit|economical`), `skill-loading` (`normal|minimal`); SessionStart passes non-default values to the assistant; `orchestrate` honours `subagent-model`.
4. **Trim always-loaded text:** global instructions and skill descriptions, measured before and after.
5. **Benchmark:** `bug-fix` ×2 and `new-project` ×1 for baseline, lite and lean (9 sessions) on the frozen branch.
6. **Docs:** usage (lean, toggles), customization, README modes table, results.
