# Two-person integration pilot

Status: frozen before execution. This small exploratory pilot is separate from the completed 93-session quality batch. It can expose coordination failures; one pair per condition cannot establish a general speed or quality improvement.

Compare baseline `f4b88b447b533d7bf02d445994fbf0ad5065827e` with candidate `2166cf2572df65b6ff16e2a2a8ff670f88d84b77`. Candidate selects `collaboration=team`; baseline has no such setting. Both install their frozen product with plugins skipped and use auto, brief replies, the same contract/context paths, local execution trust, completed setup review and existing project commands. These are project setup differences, not extra instructions in the user's tasks.

`evals/teamwork_fixture.py` fixes a Python backend and JavaScript frontend in one Git repository. Both start with the same canonical order contract, incomplete entrypoints, small existing smoke tests and an unrelated paused analytics handoff. A producer implements the backend on `feat/backend`. Its complete delivered tree is committed for transfer after preserving its original diff/history. A fresh consumer clone starts a frontend branch from the original main; the producer branch is locally available but unmerged. This transfer normalization is outside model time and is not evidence that the model committed its work.

The user requests are fixed in the fixture: implement the specified order endpoint, then connect the form to that branch's API. Neither asks for tests, modularity, engineering practices or documents. Every role gets the same local-only execution restrictions: no publication, dependencies, external services, questions or subagents.

Exactly four sessions at most: baseline backend, baseline frontend, candidate backend, candidate frontend. No retries, no selective reruns. Use `gpt-6.1-sol`, medium effort and a 480-second limit per session. Each condition runs in its own disposable container without host mounts, using the exact image in `evals/batches/teamwork-pilot.json` (Codex 0.160.1). Roles use fresh HOME, XDG, Git and Codex directories. Only repository state crosses roles; Codex history/auth is removed from the producer home before the consumer starts. Authentication is copied privately and never exported. Infrastructure failure stops the batch and remains reported.

Primary outcome: backend and consumer work together under the fixed contract. After model delivery, hidden integration checks combine the producer's backend and consumer's frontend outside model sessions and check successful string-quantity submission, zero/noninteger/boolean quantity rejection, unknown SKU and surfaced API errors. Existing smoke tests remain separate evidence. Record all failures; do not modify acceptance after seeing output.

Secondary observations: per-role elapsed model-session time; whether the consumer inspected the producer ref; useful tests and contract/handoff updates; whether either assistant confused unrelated work or claimed an unmerged endpoint was in main. Inspect actual code and transcripts, not only final claims. This pilot uses orchestrator review, not another blind numeric code-quality comparison. Installation, transfer and grading are excluded from model time; order is fixed and uncontrolled service latency is a confounder.

The bootstrap, merge-conflict detector and PR checker are primarily evaluated by isolated behavioral tests. This model pilot does not measure installation adoption, concurrent pushes, arbitrary monorepos, real HTTP servers or GitHub branch protection. Its synthetic injected transport makes cross-language data integration reproducible with no external dependencies.

Run preview: `python3 evals/teamwork.py evals/batches/teamwork-pilot.json --dry-run`. Live execution also needs `--auth PRIVATE_FILE --output NEW_PRIVATE_DIRECTORY`. Preserve session JSON, transcripts, delivered trees, product/controller hashes and test results; publish only reviewed evidence without authentication or private machine paths.
