# Search scenario (query on user input)

- Date: 2026-10-06. Claude Code 2.1.290, `claude-haiku-4-5`, five runs per condition; tack from the integration of the open pull requests, with the risk rule (#119).
- Scenario (`evals/run.sh search`): add `search_products(conn, term, max_price=None)` to a small SQLite catalogue, where the term "is what the user types in the search box". Eight hidden tests check the feature and the traps: SQL injection, `%` and `_` taken as `LIKE` wildcards, and a quote in the term. A grader test shows a parameterised query that does not escape the wildcards scores 6 of 8.

## Reading it
- Every run, with or without tack, used a parameterised query (no injection) and missed the `LIKE` wildcards. tack's process did not change that: a level picked by risk makes the model test what it thinks of, not what it does not know.
- A rule asking auto to have the `security-auditor` agent review such diffs was tried and dropped: Haiku called no agent in 10 runs (the same runs repeated attachments at 5/5).
- Together with the attachments scenario: tack helped where thinking about the input is enough (path traversal, 0/5 → 9/10 across two batches) and not where the trap needs knowledge the model lacks.

Limits: one model, five runs per condition, one scenario.
