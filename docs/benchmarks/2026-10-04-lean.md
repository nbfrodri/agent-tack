# Lean mode benchmark

- Date: 2026-10-04. Frozen revision `3d8ee12` (branch `feat/lean-mode`); Claude Code 2.1.288; requested model `claude-sonnet-5-5`; private HOME and XDG paths per session; core install with `--skip-plugins`; metrics version 2.
- Sessions: `bug-fix` ×2 and `new-project` ×1 for baseline, lite and lean (9); all completed without retries.

## Where the overhead comes from

- The startup context adds about 7,000 input tokens to the first request; lean trims a little of it.
- Most of the cost is the number of turns: every turn resends the whole context. Baseline used 3 tool calls (read, edit, done) and committed nothing; a disciplined fix needs a branch, the edit, a test run and a commit, about 7 calls before any detours.
- The rest is environment discovery: lean probed `python -m pytest`, then `uv run --with pytest`, hit a Claude Code permission prompt on a shell operator, and cleaned up a generated `uv.lock`.

## Conclusion

Lean costs the same as lite on a small bug fix and about 10% less on a new project; both keep the branch, commit and regression test the plain assistant skips. The overhead is the discipline itself plus discovery, not the instructions. The largest remaining saving is avoiding discovery: a project `AGENTS.md` that states its test command, or `harness config check-fast`, so the assistant does not probe. Baseline costs here were lower than in the earlier run ($0.042 vs $0.062 per bug fix), so ratios vary between runs; compare conditions within a run.
