# Codex subscription comparison

All **24/24 runs passed their frozen hidden acceptance tests**: two repetitions of three scenarios, with and without tack, for each of GPT-6 Luna and GPT-6.1 Sol at medium effort. There is no measured acceptance gain in this sample. tack added branch/commit discipline and useful regression tests with Luna, at higher token usage and elapsed time. A supplementary code review found a Unicode search limitation in both Luna auto runs that the hidden suite did not catch.

## Code and process

The [review of all 24 diffs](2026-10-08-codex-quality.md) separates subjective maintainability judgments from acceptance tests. Luna's six baseline runs add no regression tests; its six auto runs do, with some missing cases. Sol adds meaningful tests in both conditions. Neither more tests nor more documentation automatically earns a better code-quality score.

Both Luna auto search implementations rely on SQLite's ASCII case behavior; a separate [Unicode probe](2026-10-08-codex-unicode.json) fails for both, while both Luna baseline and all four Sol implementations pass. This supplements the original suite without changing its 8/8 verdicts or proving that tack generally worsens Unicode handling.

Auto uses a branch and makes commits in 12/12 runs; baseline in 0/12. These are process observations, not correctness points. Sol auto's attachment runs create a plan and AI log in addition to useful API documentation, taking about 3.3x baseline time. All 24 retain an untracked generated lockfile: commits do not imply a completely clean working tree.

## Reproduction

Use a disposable Linux environment with Git, Bash, uv, Python 3.12.3, pytest 8.4.2, jq and official `@openai/codex@0.160.1`. The run used Docker image `tack-eval`, no host mounts, and `--security-opt seccomp=unconfined` to permit Codex's inner namespace sandbox. The [launcher](support/codex-subscription.py) still restricts file writes to the fixture and its Git metadata; this is not a host or installer configuration change.

Check out the recorded source. Copy the launcher to a private executable directory as `codex`, make it executable, and put that directory first on PATH. Set `TACK_BENCH_CODEX` to the official CLI executable and `CODEX_HOME` to a private directory containing subscription authentication. Set `TMPDIR=/home/dev/eval-tmp` there and ensure pytest is on PATH for both conditions. Run:

```sh
python3 evals/batch.py evals/batches/codex-subscription.json --output /home/dev/evidence
python3 docs/benchmarks/support/summarize-codex.py /home/dev/evidence /tmp/codex-facts.json
python3 docs/benchmarks/support/probe-codex-search.py /home/dev/evidence/codex-subscription-20261008 /tmp/unicode.json
```

The exporter and probe were added after the experiment: obtain them from this report's revision without modifying the frozen runner checkout during a batch. Re-running the batch consumes subscription usage. Report generation and probes make no model calls. Verify exported evidence before removing disposable authentication/container. The protocol records warnings and runtime-observation limits.

Add larger real repositories and explicit Unicode/URL-decoding contracts. Do not optimize only for this small suite or claim lower spend from shorter descriptions alone.
